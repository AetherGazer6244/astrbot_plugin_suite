# astrbot_plugin_games_monitor · 游戏资讯监控

聚合《重返未来：1999》《明日方舟》官方资讯：**最新公告/活动/新闻、卡池时间、版本更新与维护窗口、
B站官方动态、兑换码**。支持指令查询、AI 对话查询、群订阅推送，WebUI 扫码登录 B站。

- 插件名：`astrbot_plugin_games_monitor`，主指令 `/游戏`
- 首发 v1.0.0，两款游戏；架构是 provider 注册表，后续加游戏（原神/星铁/绝区零等）= 加模块，不改主流程

## 快速开始

1. WebUI → 插件市场 → 从 GitHub 安装 `AetherGazer6244/astrbot_plugin_games_monitor`
2. 打开插件配置，**推送总开关默认是关的**。只想查询就直接用；要收推送就打开「启用群订阅推送」，
   再在会话里发 `/游戏 订阅 全部`
3. 直接问也行：「1999 最近有什么卡池」「方舟兑换码」

> AI 要点摘要（v1.1.0 起 `/游戏` 的默认输出）需要一个**可用的对话模型**：
> 宿主「默认配置档」里当前选中的那个。没有模型时自动退回原始公告列表，不会报错。

## 指令（8 条行为，1 条裸指令内部分发）

| 指令 | 说明 |
|---|---|
| `/游戏` | 两游戏 **AI 要点摘要**（后台预生成，秒回） |
| `/游戏 <游戏名>` | 指定游戏的 AI 要点摘要 |
| `/游戏 总结` | 同默认视图（显式写法，可加游戏名） |
| `/游戏 列表` | **原始公告列表**（不带 AI，逃生口；可加游戏名） |
| `/游戏 <游戏名> 卡池` | 卡池相关公告 + 从正文抽取的**活动时间段** |
| `/游戏 <游戏名> 兑换` | 兑换码（别名 `码` / `兑换码`） |
| `/游戏 <游戏名> 版本` | 版本更新与**维护时间窗口** |
| `/游戏 订阅 <游戏\|全部\|关闭>` | 开关本会话推送（**群内仅管理员**，私聊人人可用） |
| `/游戏 帮助` | 使用说明（轮询频率等按当前配置显示） |

游戏名写法很宽松，全半角、空格、大小写都不敏感：

- 重返未来 / 重返未来1999 / 1999 / 九九 / 重返 / RE1999
- 明日方舟 / 方舟 / ak / Arknights

二级指令不带游戏名时（如 `/游戏 卡池`）会合并两个游戏的结果。

### 为什么不是指令组

本插件用 **裸指令 + 内部路由**，不是 `@filter.command_group("游戏")`。原因写在 `main.py` 顶部，
这里也说一句：AstrBot v4.27 的指令组在**只发组名不带子指令**时会抛 `ValueError` 并回一条
「参数不足」+ 指令树，而 `/游戏` 无参必须给出两游戏最新资讯；组内也没有「默认子指令」这回事
（`@group.command("")` 注册出来的名字是 `"游戏 "`，永远匹配不上，`tests/test_registration.py`
里有一条不变式盯着这件事）。

## 与 AI 对话

三个只读工具，模型会自动调用：

| 工具 | 参数 | 什么时候用 |
|---|---|---|
| `games_news` | `game` / `category` / `keyword` | 「1999 最近有什么活动」「方舟这周更新了什么」 |
| `games_codes` | `game` | 「有兑换码吗」「有没有礼包码」 |
| `games_dynamics` | `game` | 「1999 B站发什么了吗」 |

另有幕后提示钩子：用户消息或近几轮上下文命中游戏关键词时，在 system_prompt 末尾追加一段固定提示
（必须调工具、严禁编造公告与兑换码）。幂等、整段 try/except 包住，宿主不支持 `on_llm_request` 时
退化为 no-op。两个开关：`ai_tools_enabled`、`ai_prompt_hint`。

⚠️ 工具返回值语义（AstrBot v4.27 实测）：一律 `return str` 喂给 LLM。
`yield event.plain_result(...)` 是**直接发给用户**，LLM 收不到——别搞反。

## AI 要点摘要（默认视图）

`/游戏` 出的不是公告列表，而是 AI 提炼的**要点摘要**（v1.1.0）。要点：

- **后台预生成，前台秒回**：资讯轮询发现公告变化就自动调 LLM 写缓存；
  `/游戏` 只读缓存，正常路径一次 LLM 都不调。推送正文也用摘要。
- **生成失败不缓存**：下一轮轮询自动重试；期间查询/推送自动退回原始列表并说明原因。
- **刚发公告的窗口期**：缓存还没建好时查询会**有限等待**在途生成
  （最多 20 秒，推送 45 秒），等不到才退列表。超时不取消生成——稍后再问就有了。
- **用哪个模型**：宿主**默认配置档**当前选中的对话模型（后台任务没有会话上下文）。
  想换摘要模型 = 在 WebUI 默认配置档里换模型。
- **不输出链接**：摘要与所有列表渲染都不带网址；有效信息（时间、对象、内容）直接给。
  「给我链接」走 AI 对话（`games_news` 工具的返回里有链接，喂给模型不喂给聊天）。
- **两个开关**：`ai_summary_enabled`（总开关，关了 `/游戏` 恒为原始列表）、
  `ai_summary_max_items`（每次摘要基于最新几条公告，默认 8）。

## 数据源

| 渠道 | 端点 | 稳定性 |
|---|---|---|
| 明日方舟官网 | `GET ak.hypergryph.com/api/news?category={LATEST\|ANNOUNCEMENT\|ACTIVITY\|NEWS}` | 高。官网 SPA 自己的后端，无风控，直连 |
| 重返未来：1999 官网 | `POST re.bluepoch.com/activity/official/websites/information/query` | 较高。列表接口**直接返回公告全文 HTML** |
| B站官方动态 | `spi` → `nav`(wbi key) → `feed/space`（wbi 签名） | 中。无登录能读，风控不透明 |

三条都**零成本**：资讯轮询本来就拉回两家公告全文，兑换码顺手用同一个正则扫一遍，不额外发请求。

### 实测踩过的坑（都写进了代码注释，别去"优化"掉）

- **方舟 B站官方号 UID = `161775300`**。计划书里写的 `161432940` 是同名的个人号「hc9326」，
  已修正；UID 变更改配置 `bilibili_uids` 即可，不用动代码。
- **B站 feed 请求必须带 `timezone_offset` / `platform` / `web_location`**。只带 `host_mid`+`wts`
  会**静默返回空列表**（`code=0` 但 items 为空），看着像"该号没动态"，实际是参数缺了。
- **B站对未登录请求会裁掉纯图片动态的文字正文**（实测 `major.opus` 直接 `null`）。
  这时插件会明确告诉你"没取到 + 点链接看原帖 + 扫码登录通常就能取到"，而不是留白。
- **只挂 `buvid3` 一个 cookie 最稳**，多挂主站 cookie 反而更容易吃 `-352`。
- **`code=0` 但 items 为空是风控的典型表现**（时好时坏）。插件会额外重试 2 次再认输。
- **1999 必须用 Python TLS**。curl 的 TLS 指纹会被腾讯 EdgeOne 拦，返回 `code=5001`「系统繁忙」，
  参数怎么改都没用。插件把它单独识别成"被风控"而不是"接口坏了"。
- **方舟没有兑换码体系**（补偿走游戏内邮件），所以 `/游戏 方舟 兑换` 长期「没有兑换码QWQ」是数据源现实，
  不是故障。

## 兑换码

**唯一来源是自动提取**，不提供手动登记（设计决定）：

1. **B站官方动态正文**（主来源，直播码通常发这里）
2. **公告正文兜底扫描**（1999 列表接口直接给全文 HTML，零额外请求）

提取到后入库、去重、解析过期时间：

- 写明「有效期至 X」的以公告为准
- 没写的按配置的 `code_ttl_hint_hours`（默认 24 小时）估算
- 过期的码自动剔除，列表里不会留过期码误导你
- 同一条码从动态和公告都能抽到时会合并来源

## 群订阅推送

```
/游戏 订阅          查看本会话订阅状态
/游戏 订阅 全部     订阅所有游戏 + B站动态 + 新兑换码
/游戏 订阅 1999     只订阅 1999
/游戏 订阅 关闭     取消
```

- **群内仅管理员/群主可用**，私聊人人可用（用宿主的 `event.is_admin()` 判定）
- 需要先打开插件配置里的「启用群订阅推送」总开关
- 新公告、新兑换码、B站新动态分别独立成条推送

可靠性上沿用了两条教训：

- **发送成功才记账**：`send_message` 返回 `bool`，任何一个会话发送失败就整批不记已读，
  下一轮重发。宁可给已收到的人重发一次，也不能让没收到的人永远收不到。
- **失败指数退避**：同一数据源连续失败按 60s → 2min → 4min … 退避，30 分钟封顶，
  官网凌晨抽风时不轰炸对方。

## 获取 B站登录态（可选）

**不登录也能用。** 公告、卡池、版本、公告正文里的兑换码都不受影响，
只是 B站动态这条来源可能偶尔被风控拦、纯图片动态的文字取不到。

两种方式：

1. **扫码登录（推荐）**：插件详情页 →「B站扫码登录」标签页 → B站 App 扫码确认 →
   SESSDATA 自动写进配置并热生效，无需重启
2. **手动粘贴**：在配置里直接填 `bilibili_sessdata`

SESSDATA 等于账号登录态。插件**不会**在任何聊天输出、日志或 WebUI 响应里回显它，
只暴露「是否已配置」这类布尔状态（有测试断言）。不想要登录态随时清空即可。

## 工作原理

```
定时轮询（apscheduler IntervalTrigger，无论推送开关是否打开都运行）
  ├─ 资讯轮询（默认 10min）
  │    每游戏 → provider.latest() → 与 storage.seen_ids 比对
  │    ├─ 摘要缓存过期（公告变化/首启/上次失败）→ spawn 后台 LLM 生成要点，不阻塞轮询
  │    ├─ 新条目 + 有订阅者 → 推送（优先用摘要）→ 全部成功才 mark_seen
  │    └─ 顺带扫正文兑换码 → 入库 → 有新码则独立成条推送（无订阅者也扫）
  └─ 动态轮询（默认 15min）
       每游戏 → bilibili.space_feed() → 同上；顺带扫动态正文兑换码

用户指令 / AI 工具 → 同一批 provider 方法（只读，不写已读、不写历史）
/游戏 与推送 → 摘要缓存（id 元组判版本，公告变了自动作废）
```

几个关键设计：

- **数据源抽象**：`providers/` 下每个游戏一个模块，实现 `GameSource` 协议，
  在 `providers/__init__.py` 的 `GAMES` 注册表里加一行即可。新增游戏不改 `main.py`。
- **共用 HTTP 客户端带连接退休池**：重试时**绝不**当场 `aclose()` 共享 client
  （并行请求可能还握着手上的连接），而是挪进退休池（上限 4），攒满关最老的，只在退出时统一收干。
- **存储原子写 + fsync + 60s 去抖**：用户动作（订阅/退订）一律 `force=True`；
  坏文件改名成 `*.corrupt-<ts>` 保留现场，不无声清零。
- **关键词先看标题，全不命中才退全文**：整篇公告正文里到处是「开启」「联动」，
  只看全文匹配会把「1999制作组播报」这种根本不是活动的东西选进活动列表。
- **活动/维护的时间引导词分组**：维护窗口（「维护时间：…」）不是活动时间，
  混在一张表里会让卡池视图把停服时间当成卡池时间推给用户。

## 开发

```bash
pip install ruff pytest httpx "apscheduler>=3.10,<4"

ruff check .            # 含 B 规则组
pytest -q               # 303 个用例
python tools/smoke.py --out smoke.txt          # 真机真跑，把渲染结果写 UTF-8 文件
python tools/smoke.py --out s.txt --only "游戏 1999 卡池"
```

`tests/fixtures/` 里的样本全部是 **2026-10-19 真机抓取的原始响应**，不是编造的。
解析层测试基于它们，避免"照着自己想象的格式写测试"。

`tools/smoke.py` 直接驱动真实的 `cmd_games` 并把**用户真正看到的文本**打出来。
这是照着电费插件三次「只有真跑才看得见的 bug」立的规矩——
列表方向、时间抽取、关键词误选这类问题，单测全都绿，真跑才暴露。

CI（`.github/workflows/ci.yml`）跑 ruff + pytest。

## 维护预期

正常情况下**半年到一年动一次代码**，且大概率是 B站那一头（单文件隔离修复）。

| 渠道 | 什么时候会坏 | 坏了影响 | 维护动作 |
|---|---|---|---|
| 方舟官网 | 官网大改版（年级别） | 只影响方舟查询 | 改 `providers/arknights.py` |
| 1999 官网 | 改版 / EdgeOne 收紧到拦 Python | 只影响 1999 查询 | 改 `providers/re1999.py` |
| B站动态 | 半年~一年一次（-352 / wbi 变更） | **只影响动态与码提取**，公告/卡池/版本不受影响 | 改 `providers/bilibili.py`；配置 SESSDATA 可大幅缓解 |

关键词偶尔漏新说法 = 展示缺漏，不是故障，随发现随补词表（`keywords.py`）。
